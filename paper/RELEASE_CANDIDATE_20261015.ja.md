## 新実験の可搬データ

`evidence/readout_qualification_v1/`内のファイルは許可項目を明示して取り出した
資料です。実験原本を書き換えたものではありません。

- `specification.public.json`：論理課題全体、開発／留保確認の分割、期待回答、
  正確なprompt・継続文とトークンID、再計算に必要な最小限の旧sentinelと期待得点。
- `forwards.public.jsonl`：全予定イベント、実施状態、計算形状、候補ごとの
  トークン対数確率、総和、予測位置の一致ハッシュ。
- `analysis.public.json`：保存済み得点からのCPU再計算結果。検証不成立や数値的に
  不完全な状態も、その場合はそのまま残します。
- `independent_validation.public.json`：別実装で公開入力、参照ルール、予定格子、
  記録済み一致条件、得点総和、集計を検算します。この検算器は取得コードやその
  解析をimportしません。明示的なadapterが原本と公開用データでの検算一致を確認し、
  検算コードと公開ファイルのハッシュを記録します。未完了・数値条件不成立のrunは
  評価不能と明記し、完全run用の検算器を通った扱いにはしません。
- `run_summary.public.json`：限定された計算量と実施状態。実行またはソース結合の
  エラーがあったかを真偽値で残します。ホスト識別情報を含み得るエラー本文は
  除外しますが、成功扱いにはしません。
- `runtime_dependencies.public.json`：パッケージ／Pythonの版、得点設定、
  モデルファイルと実装ソースのハッシュ。ローカルパスやモデル・tokenizer本体は除外します。
- `projection_binding.json`：元の仕様・実行ファイルのハッシュと取得時ソースの
  ハッシュ。機械内のパス、プロセス記録、エラー文を公開せず、保持原本との対応を示します。

作成時には実行前に保持した仕様ハッシュを要求し、原本・ソース・入力一覧の結合を
検証します。項目の取り出し前後で解析が完全に一致することを要求し、完全runの
条件を満たす場合は別実装でも一致を検算します。原本を変更せず、非公開の参加者資料を読みません。
モデルforward、tokenizer呼出し、ダウンロード、GPU処理、外部アップロードも行いません。

## ローカルでの作成

まだ存在しない新しい出力先を指定します。以下は実行例であり、入力や完成候補が
すでに存在するとの宣言ではありません。

```bash
python3 -B paper/scripts/build_release_candidate_20261015.py build \
  --pdf output/pdf/glyphprobe_revised_preprint_20261015.pdf \
  --specification validation/readout_qualification_v1/specification.json \
  --expected-specification-sha256 5273b1f86db4ee956659a94ca7f047856e86b5f857fdf66efc5d96e5f85c487f \
  --run-directory validation/readout_qualification_v1/run4640 \
  --output output/artifacts/glyphprobe_revised_preprint_20261015_candidate_v2.zip
```

v2はmacOSのシステム一時フォルダでの検証を修正した版であり、論文と実験得点は
変わりません。既存の候補アーカイブは保存します。再作成時は別の未使用の出力名を選びます。

作成にはPythonとPDFプライバシー検査用の`pypdf`が必要です。入力欠落、結合の変更、
既存出力、安全でないパス、非公開パケット識別子、秘密情報らしい文字列、公開用
データ内のローカル／ネットワークパスを検出すると停止します。正確な許可リストと、
範囲を限定したリテラルTeX依存関係を使い、リポジトリを丸ごと保存しません。
これは保守的な機械検査であり、著者の最終プライバシー・権利確認の代わりには
なりません。著者名と明示的な架空人物の刺激名は意図した収録です。匿名査読用の
パッケージではありません。

ZIP時刻は再現可能なパッケージ作成のためだけに2026年10月15日に固定します。
実験日時や公開日時ではありません。同じ圧縮環境で同じ内容から同じアーカイブを
作成できます。元ソースや実験記録の時刻は書き換えません。

## 展開後の検証と再計算

展開先の内部に別ファイルを作る前に、そのルートから実行します。

```bash
python3 -B paper/scripts/build_release_candidate_20261015.py verify .
```

全ファイル一覧・バイト数・ハッシュを確認し、読出し検証の解析と別実装での検算を
Python標準ライブラリだけで再計算します。2つの実装は
`scripts/readout_qualification_v1.py`と
`scripts/validate_readout_qualification_v1.py`です。公開用ファイルのadapterは
パッケージ作成スクリプト内にあります。原本用検算CLIは元のファイル名と記録を
必要とするため、公開用データには上記コマンドを使います。
成功が示すのはパッケージの整合性と保存済み得点の
計算です。意味的妥当性、独立した人間の確認、未観測の機構を立証しません。
旧アーカイブには独自の検証器と再計算手順があります。
