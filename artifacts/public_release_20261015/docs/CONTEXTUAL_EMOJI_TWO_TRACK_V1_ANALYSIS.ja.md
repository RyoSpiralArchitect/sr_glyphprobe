# 二系列の開発試用：解析の範囲

[English](CONTEXTUAL_EMOJI_TWO_TRACK_V1_ANALYSIS.md) · [設計](CONTEXTUAL_EMOJI_TWO_TRACK_V1.ja.md)

## 著者回答の非公開解析

解析は、既に回答・取得記録と結び付いたv1の画面や実行器とは分離する。
後の解釈に合わせて画面、対応する設計書、v0の記録、元の回答履歴を編集しない。

1. `scripts/analyze_contextual_emoji_two_track_author_v1.py describe` は、確定済み
   回答を読み取り専用で検証する。割当やモデル結果を開かず、評価票・画面のハッシュ、
   要求ID、状態の再生、時刻、全分母を調べる。
2. 非公開の解析フォルダに日英の `PHASE_ONE` を書き、`seal` を実行する。
   時刻とハッシュは今回の割当・モデルを見る前の考察を記録する。過去の知識を
   消したり、事前登録に変えたりするものではない。
3. キーを開く前に封印と結び付けた `comparison_exposure.json` を記録する。
   `scripts/compare_contextual_emoji_two_track_author_v1.py` はその対応を検証し、
   独立の数値検査と全候補の再計算を行い、場面・問いの文字列一致で人の回答を照合する。
4. `scripts/diagnose_contextual_emoji_two_track_readout_v1.py` は保存済みの系列値を、
   分岐する回答tokenと続くピリオドへ分解する。事後診断であり、主指標は置き換えない。
5. `scripts/build_contextual_emoji_two_track_author_notebook_v1.py` で非公開の
   実行可能な補助notebookを作る。nbformat、nbclient、ipykernelのある環境で最初から
   最後まで実行し、回答履歴と保存済み解析を再計算する。

各段階は出力の上書きを拒否する。実際の評価票、割当、元回答、考察、回答と結び付いた
解析はこのMacのGit・SpiralShare外に保つ。炉の作業場所へ送らない。
repoには汎用解析コード、架空のテスト、本手順だけを置く。非公開の出力にもソースの
ハッシュを添える。後の解析変更は記録の手修正でなく、新しい出力版として残す。

## 分母と解釈

評価票は24場面・36の実質判断で、性質の一致12問と、自然な文脈12場面×2問からなる。
36独立課題ではない。判断保留、明示的な回答辞退、未回答は区別し、保留をNoにしない。
任意の品質欄が空欄でも、良好とは解釈しない。著者の既知の接触履歴と自己申告を分ける。

人とモデルの一致は、人が二値回答したものとモデルの同点でない採点で数える。
この回答によって選ばれた部分集合は、人の正解に対する精度ではない。
主な照合は同じ肯定形の問いを使う。否定形を意味の向きへ戻した比較は、参加者が
答えていない感度分析として扱う。作者が定めた一致や論理対照は独立した人の正解ではない。

モデルの全一覧は、全ての手がかり種・群・命題・極性、手がかりなし、明示的な完了／
不明の対照を残す。真か／偽かの問いで同じ命題を保つには、文字通りのYes／Noを反転する
必要がある。二つの問いは繰り返しの観測であり、課題数を増やさない。
文脈×手がかりの差は、系列尤度の記述的な交互作用であり、因果や絵文字優位を確立しない。
主指標は元の回答系列全体のlog確率のままにする。tokenだけの診断では同点も残す。

数値の整合性と意味測定への適合性を分ける。完全に再現できる取得でも、明示的な証拠や
質問反転の対照を満たさないことがある。それは今回のモデル・問題文・採点形式の解釈を
制限するが、モデル全般の能力不足を確立したり、別の実験を無効化したりするものではない。
著者試用は、より小さい測定方法の動作確認を設計する材料になる。独立した評価者や新しい
課題群の代わりにはならない。今回の解析では新しい計算、原稿数値の変更、参加者募集、
Gitのpush、非公開データの公開は行わない。
