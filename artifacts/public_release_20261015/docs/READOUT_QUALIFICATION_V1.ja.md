# 明示的な報告を用いた応答測定の適格性確認

[English](READOUT_QUALIFICATION_V1.md)

計画日：2026年10月15日。モデル出力を見る前に定める、有限の例集合による
開発実験。内部での事前仕様であり、外部の事前登録ではない。過去の評価指標・
結果・参加者記録は変更しない。外部公開とDOI登録は別の操作とする。

## 問いと貢献

同じLlama 3.2 3B baseと実行形状を揃えた採点方法を用い、明示的な報告と
尋ねる命題を固定して、質問の入れ子構造と回答形式を変えると、どの失敗が残るか。
以前の文脈実験では、明示的な完了報告の対照にも失敗した。今回は新しい文章だけの
事実を用いて測定方法を点検する。絵文字の意味を仮定せず、モデルの選好を人の判断と
扱わない。

## 固定する入力集合

- 新しい事実の基本例32件。4つの領域・テンプレート群に各8件を置く。
  2群16件を開発用、別の2群16件を留保確認用とする。全入力と解析を最初の
  forward前に固定し、開発結果を見た調整は行わない。
- 報告はPの明示、not-Pの明示、不明の3状態。それぞれについてPとnot-Pを問う。
  対象は実際の出来事の真偽ではなく、報告が何を明示しているか。不明な報告は
  どちらの主張も支持せず、出来事が明示的に偽だとは符号化しない。
- 質問は直接形 `Does the report explicitly state that {proposition}?`、
  肯定入れ子形 `Is it true that the report explicitly states that {proposition}?`、
  否定入れ子形 `Is it false that the report explicitly states that {proposition}?`。
  最後だけ、同じ証拠命題に対する期待回答を反転する。
- 回答は従来の完全なYes/No文、最小のYes/No、AがYesを意味するA/B、
  AがNoを意味するA/Bの4形式。任意ラベルの対応は明記し、表示順はどちらもA、B。
- 32 × 3 × 2 × 3 × 4 = **2,304候補対／4,608科学的系列forward**。
  過去の一致確認32回を加え、**最大4,640回**。これは32例・4テンプレート群の
  反復測定であり、独立した2,304課題ではない。

完全な入力文、対応、論理的参照、token ID、ソースとモデルのhash、実行環境、
全予定を準備仕様に結び付ける。保護対象の過去bank、非公開質問票、CLDR目標は読まない。

## 実行前に固定する判定

1. 数値面の受理には全予定行、有効なtoken境界、有限のtoken和、共通接頭部分の
   完全一致、実行前後の過去確認例の完全一致を必要とする。logit比較には最初に
   異なる回答tokenの予測位置も含め、共通回答tokenがゼロの空比較では通過させない。
2. **主たる有限集合の通過条件**：直接質問・最小Yes/Noで、留保確認の**96条件**
   （16例 × 3報告 × 2命題）がすべて正しいこと。同点ゼロ、16/16例が各6条件正答。
   事実と支持規則が明示的なので厳密な操作上の基準を置く。母集団精度の推定や、
   意味理解に校正された閾値ではない。
3. **別個のラベル頑健性条件**：直接質問の両ラベル対応で留保確認**192条件**が
   すべて正しく、同点ゼロ。両方誤った回答の一致は通過しない。主条件だけ通過した
   場合は、固定した最小Yes/No形式に限った適格性として記載する。

全形式と失敗を報告し、最良形式の事後選択や過去の推定量の置換をしない。
p値や母集団区間は導入しない。後の絵文字への転用は別途判断し、今回の実行には
含めない。以前の課題の再測定を新しい例数に数えない。

## 解析と限界

予定・完了・失敗の全分母、分割・群・報告状態・命題・質問・回答形式別の正答と
margin、クラス均衡精度、各例6条件の全正答、同点、ラベル対応の一致と正しさ、
直接／入れ子および肯定／否定の一貫性を報告する。直接質問の支持率は1/3なので、
常にNoの基準は単純精度2/3、クラス均衡精度1/2となる。基準を必ず併記する。
系列全体と最初に異なる回答tokenの採点は別の推定量として示し、残りの継続部分の
寄与も捨てずに報告する。

ラベル対応は指示追従の要求を加える。回答形式は文言と採点する末尾を共に変えるため、
差を句読点だけの原因とはしない。質問形は言語的要求を変えるが、神経的な介入ではない。
明示的支持は文字列照合でも解け、通過は文脈解釈の十分な証拠ではない。留保テンプレートも
著者側で構成し、人による独立検証ではない。絵文字固有性、モデル間再現、自由生成、
新しい機構、人の独立確認は主張しない。

## 実行と停止

既存の固定済みBF16 Transformers/CUDA・eager attentionとcheckpointを使う。
chat template、download、学習、生成は行わない。今回のlogitと過去結果の一致確認には
その実装が必要であり、炉の汎用TensorRT生成サービスへの変更は測定を変えてしまう。
管理環境は変更しない。候補対を同じ長さにpadし、同じFP32正規化範囲で実tokenのみを足す。

読込前と各forward前後で占有を調べ、他GPUプロセスがあれば停止する。全予定の未実行行を
保持する。時間上限1,800秒、Torch割当上限9,728 MiBとdriver余裕512 MiB。
読込前12,288 MiB、forward境界4,096 MiBの空きを要求する。自動再試行、他処理の変更、
暗黙の環境切替は行わない。炉の隔離checkoutで実行し、保存した結果をCPUで解析して、
集計を独立に検算してから原稿へ反映する。
