## 1. 何を確かめたか

対象は、判定境界が動いた3課題の入力、保存済み接頭列差の最大入力、長さ・carrier別の規則的な4対照である。既知の結果に基づく選択なので、数値差の出現率は推定できない。

各入力で、元のA/B採点を2回ずつ、長さをそろえたA/B採点、promptと共通接頭列だけの採点を行った。元条件は過去と同じBF16・eager attention。padding条件では実tokenの位置とmaskを明示し、同じ大きさの予測位置領域をFP32で正規化してから有効な候補tokenを取り出した。接頭列だけの実行は形状が異なるため、比較用として扱った。

[初回の実行前停止とCPU再検算の別版化](CONTEXTUAL_EMOJI_PREFIX_PREFLIGHT_ADDENDUM_V0.ja.md)は、すべてモデル実行前の出来事である。初版commit `d725960` は0 forward。取得commit `41ff805` は仕様 `751a81c0…` を使った。変更したのは補助的なCPU集計の計算定義で、旧記録から新参照への値の変更6件を別記録に残した。Linuxで元の式を再計算した際の旧記録との差7件も保存した。どちらもモデル確率の差ではなく、モデル比較の許容差は追加していない。

## 3. 選ばれる候補が同じでも、スコアは動く

`s = log P(A | prompt) − log P(B | prompt)` とし、各候補文全体のtoken対数確率を合計する。下表は表示用に丸めた値で、raw記録には全精度を残す。「旧接頭列差」は接頭列の総和どうしの差であり、単一tokenの最大差ではない。padding後の接頭列差は全行で厳密に0だった。

| 候補組／carrier／課題／文脈／手がかり | 旧接頭列差 | 元のs | padding後のs |
| --- | ---: | ---: | ---: |
| original / emoji / affect_01 / p / b | +0.018725 | +0.010518 | +0.062433 |
| explicit_negation / emoji / affect_03 / q / b | −0.056777 | +0.429805 | +0.482039 |
| adjective_pair / emoji / thermal_04 / p / b | +0.082370 | −2.544021 | −2.563891 |
| original / emoji / thermal_04 / p / a | +0.187710 | +1.867091 | +1.656820 |
| original / emoji / completion_02 / p / a | 0 | −1.122747 | −1.122747 |
| original / word / completion_02 / p / a | 0 | −0.297513 | −0.297513 |
| adjective_pair / emoji / affect_01 / p / a | +0.064435 | +1.723096 | +1.773870 |
| adjective_pair / word / affect_01 / p / a | 0 | +1.150312 | +1.155262 |

`|s_padded − s_original|` の最大値は **0.2102706432 nats**。同じ候補内のtoken対数確率の変化は最大 **0.1302242279 nats**。接頭列だけを別形状で実行した場合、padding条件との接頭token対数確率差は、このパネルで最大 **0.0535953045 nats** だった。

最終行では、旧接頭列差が0でも候補全体のスコアは動いている。等長対照では元の候補スコアを保った一方、接頭列だけの別形状実行とは差があった。提案する実行条件そのものについて一致を調べる必要がある。

original emoji `affect_01/p/b` は、以前の保存済みスコアのtail-only診断ではsが+0.010518から−0.008207へ変わった。今回、形状をそろえて全文を採点すると+0.062433となった。**保存済みの接頭列差を引く処理は、実行形状をそろえた再採点の代わりにはならない。** 続きの部分の確率も、実行形状に伴って変わり得る。

## 4. 解釈と論文に書ける範囲

意図的に選んだこのパネルでは、モデル入力と正規化領域の形状をそろえ、位置とmaskを明示すると接頭列の不一致が消えた。元条件の完全再現と反復一致は、今回の差を単なる実行ごとの揺れで説明する余地を狭める。ただし、複数の実行条件を一緒に変えており、特定kernel、BF16演算、maskのどれが原因かまでは分離していない。FP32の参照値や、確率の絶対的な正確さを示す証拠もない。

各課題の1入力だけからH、効果の反転、全4条件一致は再計算できない。以前のtail-only解析で全H符号が保たれたことも、新しい全文採点でHが保たれる保証にはならない。24課題は引き続き、著者ラベルによる探索用の開発資料である。人の解釈、候補文の同等性、新課題群への一般化、emoji固有の機構は、この診断では検証していない。
