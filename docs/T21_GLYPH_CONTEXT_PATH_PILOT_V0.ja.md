# T21: glyph位置の文脈経路パイロット

[English](T21_GLYPH_CONTEXT_PATH_PILOT_V0.md) | [T20](T20_LEXICAL_ALIAS_OPTIMIZED_SUBSPACE_CAUSAL_V0.ja.md)

## 目的と現時点の境界

T20で観測された読み出し状態交換の非対称性を追う探索パイロットである。
対象は**T20で評価済みの384件**、置換元と固定競合候補は**T19で使用済みの
source 128件**に限定する。残る**195件の選定・トークン化・モデル実行・内容の
確認は行わない**。パイロットの実行器には予備集合の選定や確認実験のコマンドを
設けない。commit `896b942` の原稿を投稿可能な基準版として保持する。

同じ項目のcodepoint表記から得た状態で読み出し位置の残差状態を置換した後、
glyph位置から届く後半attentionの情報が対応keywordの読み出しに寄与するかを問う。
T20と同じLlama 3.2 3B BF16のblock 21と24を候補の起点とする。

## 介入と対照

起点より後のblockで、**glyphトークン数が同じ**別のsource絵文字から得た
RoPE適用後のkeyとvalueを移植する。変更できるのは読み出しqueryのattention出力
だけである。ほかのquery出力、読み出し位置自身のkey/value、モデル重み、
残りの計算は保持する。対象ごとに決定的に選んだ異なる2件を置換元として平均する。

glyph位置への置換を、同数の直前suffix位置への置換と比較する。広い対照では
読み出しより前の全位置から届く情報を置換し、その後に対象自身のglyph位置、
または同数のsuffix位置の情報だけを戻す。読み出し状態を置換しない条件も設け、
通常の依存と置換後の依存を区別する。別項目への置換後に元の値を全て戻す条件は、
介入なしのreset条件と完全一致しなければならない。これは実装検証である。

pipeとarticleの両carrierを4、8トークン後に読み出す。4トークン後はT20との
接続を担う。**次段階への進行判断には8トークン後を用いる**。この条件では
glyph位置や同数のsuffix位置を復旧しても、ほかに置換された過去位置が残る。
3トークンのglyphを4トークン後に読む場合、一部の対比は代数的に同一になる。
これらを独立した裏付けとして数えない。

## 測定

主な連続指標は、対応keywordとのcosine類似度から、**固定した128件のsource
keyword**との最大類似度を引いた値である。評価集合の件数にかかわらず、各項目に
正解1件と競合128件を用いる。対応keywordと置換元keywordの類似度差、keyword
top-1、codepointの読み出しも報告する。候補集合はqueryと同じcarrier・距離で
読み出す。この指標の採用によって、過去のT20の結果や判定規則を変更しない。

項目内では2件の置換元、進行判断ではさらに距離8の2つのcarrierを平均する。
bootstrapの単位は対象項目とし、sourceの置換元・候補集合を固定した条件付きの
区間を求める。繰り返した文脈を独立項目として数えない。

## パイロットの進行規則

完全一致による実装検証と全件の取得が必要である。いずれかの起点で、次の
bootstrap 95%区間の下限が全て正であることを要求する。

1. reset条件と、全過去位置を別項目に置換した条件の校正対比。
2. glyph位置の置換による絶対的な低下。
3. 同数のsuffix位置の置換に対する追加の低下。
4. 全過去位置の置換後、glyph位置を復旧することによる増加。
5. 同数のsuffix位置の復旧に対する追加の増加。

これは**探索上の選別**であり、多重性を調整した確認的検定ではない。
両起点が通過した場合は、対比2〜5の下限の最小値が大きい方を選び、同点なら
小さいblock番号を選ぶ。通過が認めるのは別の確認実験計画の準備までである。
195件にアクセスする前に、効果量の意味、検出力、多重性、候補集合、停止条件を
別途記録する。校正不成立なら経路仮説は未解決とする。校正成立後の不通過が
制約するのは、この介入と指標であり、ほかの経路まで除外しない。

## 実行と完全性

設定: [`t21_glyph_context_path_pilot_v0.yaml`](../configs/t21_glyph_context_path_pilot_v0.yaml)。
実行器: [`t21_glyph_context_path_pilot_v0.py`](../scripts/t21_glyph_context_path_pilot_v0.py)。

実行前の仕様記録に、ソースファイル、選定記録のハッシュ、トークン列、置換元の
番号、既測定モデルの識別情報を結び付ける。出力の新規作成を強制し、完成した
chunkは不変として再開時にもハッシュを検証する。8件の実装canaryを先行させ、
その後384件を実行する。他のGPU実行が見つかった場合は次の項目境界で終了し、
実行1回あたり90分の上限を設ける。

残差状態とquery別key/valueへの介入は管理された生成用インターフェースでは
扱えないため、Transformersのeager attentionを使う。既存環境とsystem CUDAは
変更しない。文章生成は行わない。新しい証拠を別途検証するまで、既存原稿と
匿名archiveは変更しない。
