## 1. 目的と主張の範囲

これは、本人の自由意思でローカル環境において行う、**著者本人による開発用の初期自己評価**である。独立した人手検証、確認的検定、一般の読者の成績推定ではない。既存の24シナリオは著者が作成し、モデル結果の集計も以前に議論している。今回ラベルやスコアを隠しても、その履歴は消えない。著者本人であること、これまでの関与と結果への接触、項目の見覚えを記録し、盲検や独立評価とは呼ばない。

個々の項目について、回答キーやスコアのフィードバックを見ずに判断したとき、著者本人にとって応答の区別を解釈できるか、表現に問題がないかを確かめる。曖昧さ、言い回し、手順上の不具合を見つける用途であり、独立した意味の妥当性、評価者間一致、絵文字と単語の同等性、因果関係、新しい課題群への一般化を確立するものではない。著者ラベルは後から比較する期待値であり、独立した人手の正解ではない。

今回は、項目を一つずつ提示する最初の解釈評価だけを対象とする。応答表現どうしの同等性評価と絵文字・単語の比較評価は後に回し、この段階では書き出しも表示もしない。独立した評価者と、独立して作成する真に新しい課題群の検討は未決定のままとする。保護対象の歴史的bankは開かない。

## 2. 項目の固定と割当て

入力には、既存の開発用シナリオと候補応答パネルだけを使う。収集前に、評価セットのmanifestへ正確なパス、版、SHA-256を固定する。モデルのスコアを収めたファイルは選択の入力にしない。新しいシナリオの作成、英語の刺激文の言い換え、好都合な事例の選別、期待値やモデル結果が不都合な項目の差し替えは行わない。

既定の項目は、既存の重複しない24シナリオである。6課題群に4シナリオずつあり、各シナリオについて既存の文脈 p/q × 手がかり a/b のいずれか一つを選ぶ。その割当てでは、各課題群に4通りの組合せが1件ずつ現れるようにする。各シナリオは1回だけ提示し、絵文字／単語のいずれか一方と、候補応答の表現1組を割り当てる。v0には手がかりなしの項目を含めず、その条件についての結論も出さない。

最初の回答より前に、以下の条件を満たすランダム割当てを一つ固定する。

| 集計単位 | 必須件数 |
| --- | --- |
| 重複しないシナリオ | 24件。各課題群に文脈 × 手がかりの4通り |
| 伝達形式 | 絵文字12件、単語12件 |
| 候補応答の表現 | 既存の3種類の応答ペア表現に各8件 |
| 伝達形式 × 応答表現 | 6通りの各組合せに4件 |
| 応答の表示順 | 元の順序12件、逆順12件 |

これらの制約の中で提示順と条件の割当てをランダム化し、seedとアルゴリズムの版を記録する。割当ての選択には、入力項目一覧と事前に定めた件数条件を使い、著者の回答ラベルやモデル結果は使わない。固定したアルゴリズムで最初に条件を満たした割当てを採用する。その他の課題群・文脈・手がかりのクロス集計も記録するが、高次の組合せがすべて均衡しているとは主張しない。項目一覧や割当てが条件を満たさなければ収集前に止め、手順書を明示的に改訂する。黙って項目を除外、重複、差し替えしてはならない。「結果を使わない割当て」とは、この割当て手順についての限定的な説明であり、既に結果に触れた開発用素材や著者の知識が結果から独立しているという意味ではない。

英語の目標・メッセージ・応答文は、固定した入力のままとする。日英切替で変更してよいのは説明と画面のラベルだけであり、刺激文を翻訳・変更してはならない。それらの項目本文を固定する評価者向けデータ全体のhashと、保存した各操作に付随する説明言語を残す。保存操作を伴わない言語切替は記録せず、表示言語の完全な履歴とは扱わない。

## 3. 非表示にする情報と回答前の固定

人による最初の回答を受け付ける前に、次の3つを固定し、それぞれのhashを記録する。

1. **評価者向けデータ：** 意味を示さない表示ID、変更していない刺激文、表示順に並べた応答文、許可した操作と説明だけを含める。
2. **著者ラベルキー：** 入力元で定めた期待値・方向づけと、その入力元との対応を変更せず保持する。今回の回答を受けてラベルを修正しない。
3. **割当て・順序キー：** 表示IDと、元のシナリオ、課題群、文脈、手がかり、伝達形式、応答表現、提示順、応答の表示順との対応を保持する。ランダム化の記録も含める。

2つのキーとモデル結果は、HTTPで配信を許可する範囲の外に置く。評価者向けデータ、クライアント側の状態、URL、評価者用ダウンロード、評価者に見えるログやメタデータにも含めない。引き渡し前に、実際に配信するファイル、経路、応答内容を検証する。手順書への記載だけでは、情報が隠れている証拠にならない。「回答キーは表示されない」と案内するには、この検証が必要である。評価セット・説明文の版と3つのhashは別のmanifestに記録し、秘密にする対応関係を評価画面へ公開しない。

これは手順上のスコア・ラベル非表示であり、リポジトリ所有者が意図的にローカルのキーを開くことを防ぐ仕組みではない。著者は、評価開始から解釈評価全体の確定まで、キー、モデル結果、以前の結果の議論、比較パネルを参照しない。絵文字か単語か、実際の表現、見覚えのあるシナリオ、覚えている期待値は隠せない。これらが盲検化されているとは説明しない。

## 4. 評価者への説明

表示された目標・メッセージと、2つの応答を読んでください。著者が意図した回答を思い出したり、モデルの出力を予測したりせず、表示内容から何が支持されるかを判断してください。流暢な応答でも、メッセージに沿っているとは限りません。どちらか一方を選ぶ必要はなく、不確かだという回答も有効です。

解釈について、次のうち一つを選んでください。

| 選択肢 | 意味 |
| --- | --- |
| 1番目 | 1番目の応答は表示された目標・メッセージに沿っており、2番目は沿っていない。 |
| 2番目 | 2番目の応答は表示された目標・メッセージに沿っており、1番目は沿っていない。 |
| 両方 | 表示内容を同じように読んだとき、両方の応答が適切である。 |
| どちらでもない | 判断できる程度には内容を理解できるが、その読み方ではどちらの応答も適切でない。 |
| 解釈が分かれる | 内容に複数のもっともな読み方があり、読み方によって適切な応答の判断が変わる。 |
| 判断できない | 内容を十分に理解できない、または何を基準に判断すればよいか分からず、上のいずれかを選べない。 |
| 回答を控える | この項目の解釈については回答しない。理由の記入は不要。 |

読み方によって選択が変わる場合は「両方」ではなく「解釈が分かれる」を使います。「両方」は、同じ読み方で両方を受け入れられる場合です。メッセージを理解したうえで両方を退けられる場合は、「判断できない」ではなく「どちらでもない」を使います。これは選択肢の定義であり、特定の項目を期待された回答へ誘導するものではありません。任意のメモ欄には、読み方、不確かさ、表現上の懸念、その他の気づきを書けます。記入は必須ではありません。

各項目について、以前の作業でこのシナリオや候補応答を見た覚えがあるかを、任意で**ある／ない／分からない**から記録できます。確認のために資料を調べる必要はありません。見覚えが未回答でも、解釈の回答は保存できます。その欄は欠測として残し、「ない」や「分からない」には置き換えません。見覚えは記憶に基づく自己申告であり、実際の項目閲覧を証明するものではありません。セッション単位で、英語の理解への自信を**無理なく読める／ときどき難しい／難しい／答えたくない**（`comfortable`、`sometimes_difficult`、`difficult`、`prefer_not_to_say`）から自己申告してください。これは評価時の背景を記述する情報であり、参加資格の足切りや、不都合な回答を除外する理由にはしません。

解釈の選択後、任意で、プロンプト、1番目の応答、2番目の応答それぞれの自然さを別々に評価できます。選択肢は、**問題なし**（理解でき、特に言い回しの問題を感じない）、**不自然**（理解できるが、言い回しが不自然・ぎこちない）、**分かりにくい**（自然さを評価できるほど理解できない）です。これは言語表現の評価であり、応答が目標に沿っているかとは別です。空欄は任意項目の欠測として記録し、解釈の回答を無効にはしません。

v0には、採点付きの例題や期待される回答を教える練習問題を設けません。操作だけの説明が必要な場合も、開発用の刺激文や期待される回答は見せず、収集前の説明文改訂として記録します。

## 5. 中断・再開、編集、確定

中断・再開と、本人の意思による終了を可能にする。再開時には固定済みの割当てを使い、済んだ回答に応じて並べ直さない。確定前は、戻って回答を修正できるようにする。元の値、変更後の値、変更時刻を追記型の操作履歴に残し、理由は任意とする。履歴を消して上書きしない。記録するのは評価全体の開始と保存した操作であり、項目表示の計測は行わない。実際の項目の提示と再閲覧は**未測定（UNMEASURED）**である。開始や回答保存の記録から、いつ、何回、または全項目を見たかどうかを確定することはできない。記憶に基づく接触は見覚えの自己申告として残し、観測した閲覧履歴には置き換えない。

確定は項目ごとではなく、**解釈評価24件の全体**に対して行う。明示的な確定操作の前に、回答済み・回答を控えた項目・未回答の件数を表示する。欠測を明記したまま確定できるようにし、推測回答を強いたり、空欄を「回答を控える」に置き換えたりしない。確定時の回答一式と操作履歴のhashを固定する。その後の訂正は、日付付きの別の追記・裁定として扱い、生の記録や確定時の記録を置き換えない。

確定前に、項目ごとの正誤、ラベル、スコア、途中の一致率、モデル結果を返してはならない。確定後も回答キーや結果を自動表示しない。後から結果を比較したりラベルを開示したりする場合は、別途明示的な依頼を必要とし、その情報に接触したことを記録する。開示後の回答を、フィードバック未接触の回答として扱わない。後日の比較パネルによって、今回の回答が遡って独立評価になることもない。

## 6. 記録、プライバシー、集計

仮名の評価者IDを一つ使い、役割を `author` として記録する。手順書・説明文・項目・入力元・割当ての版、3つのhash、評価全体の開始と保存した操作・編集の履歴、各保存操作時の説明言語、生の解釈回答、任意メモ、見覚え、英語理解の自己申告、任意の自然さ評価、欠測、セッションの状態、確定状態、その後に申告された情報接触と追記を保持する。最初の回答より前に、手順書と配信する画面・説明文のファイルを固定して操作履歴にひも付け、既存の回答を異なる説明のもとで黙って再開しない。実際の項目閲覧・再閲覧と、保存操作を伴わない言語切替は未測定のままとする。生の判断と、後から行う著者ラベルとの比較や裁定は分けて保存する。
