## 変えるところ

現在の主要な測定対象はCLDRキーワードの検索である。読者がこれを語彙対応の研究と
読むのは、測定内容に即している。命名を改善すると読みやすくなるが、主張を広げるには
別の振る舞いを測る指標が必要になる。

改訂の中心に置きたい問いは、**絵文字の情報はいつモデルの応答を変え、その寄与を
どの内部メッセージが運ぶのか。** これは研究上の問いであり、成立済みの結果ではない。
既存の検索・介入結果は、その出発点と現在の測定で届いた範囲を示す。

読者向けの説明では内容が伝わる実験名を使い、T19/T20/T21は補遺の対応表、コード、
過去の記録に残す。日英の実験ガイドに、名称・問い・対象数・結果と共通の具体例をまとめた。
生の絵文字テキスト、公式名、キーワード、コードポイントの文字列表記、読み出し位置を、
最初の具体例でまとめて説明する。

原稿は次の科学的なつながりに沿って組み直す。

1. 内部状態から、どんな語彙関係を読み取れるか。
2. 固定・最適化した低ランク部分空間への介入で、どこまで分かったか。
3. 読み出し状態を置換すると何が変わり、通常の出力とは何が違うか。
4. 新たに指定する自然文脈の実験で、絵文字由来の情報と応答を結び付けられるか。

4番目の研究は未完了であり、開発用応答パイロットを因果・確認結果とは扱わない。
著者の更新された方針は、PDFを改訂し、
新しい研究を完了してから公開する、という順序である。完了に肯定的な結果を要求せず、
負の結果や校正不成立も残す。本計画書だけを根拠に、外部公開やDOI予約を実施しない。

## 既存の証拠で補える設計上の論点

0.02は事前に指定した運用上の閾値だった。確認した記録には、意味理解にとって実質的な
大きさだと裏付ける根拠はない。その限界を説明し、当時の判定を変えずに感度を示す。

`scripts/summarize_revision_sensitivity_v0.py`は、明示した5つの集計結果ファイルだけを
読み、そのSHA-256とともに
`validation/post_review_revision_20261007/sensitivity_summary.json`を生成する。
モデル、tokenizer、保護対象bank、ランダム化検定、bootstrapは使わない。保存済みの
統計検定を固定し、結果を知った後で、観測効果の閾値と深さ別平均を調べる。

| 効果の閾値 | 二つの観測効果がともに閾値以上の構成 | 主要4構成の内訳 |
| --- | ---: | ---: |
| 0.02 | 9/9 | 4/4 |
| 0.03 | 9/9 | 4/4 |
| 0.04 | 8/9 | 4/4 |
| 0.06 | 6/9 | 4/4 |
| 0.08 | 4/9 | 3/4 |
| 0.09 | 2/9 | 1/4 |

記録済みのpartial-conjunction p値は0.0027のままで、別の閾値や深さに対するp値を
新しく計算したわけではない。後期の3深さを一つずつ取り出した平均と、一つずつ除いた
3通りの平均でも、全9モデルの両成分の点推定は0.02を超える。これらは記述的な頑健性の
確認であり、6回の新たな確認実験ではない。

二つの低ランク介入研究は、効果の閾値をゼロに下げても成功サイトが生じない。
保存された各サイトで、必要性・十分性の少なくとも一方の区間下限が非正で、
site IUT p値も0.05を上回る。最適化実験の主要サイトは、当時の規則では較正不能のまま。
事後に較正閾値を変えても、機構の証明にはならない。

block 21/24/27は、以前から引き継いだ相対深さ0.75/0.875/1.0を、28 blockのモデルで
`min(L - 1, floor(f * L))`により解決した0始まりの番号である。数値の由来は説明できるが、
block 24が主要サイトとして唯一適切だとする科学的根拠にはならない。次の研究では、
開発用データで少数の層範囲を比較し、新しいシナリオ系列を評価する前に選択を固定する。

## 追加実験に一つの役割を与える

[日英の実験案](CONTEXTUAL_EMOJI_CAUSAL_TRANSFER_PLAN_V0.ja.md)では、文脈と絵文字を
交差させ、通常の言語モデル出力を採点し、絵文字位置から届くメッセージを双方向に交換する。
新しい評価の正解はCLDRラベルから作らず、読み出し残差のリセットも使わない。

刺激の妥当性、通常状態での応答への寄与、同じ指標への因果介入、という順に進める。
小さな開発集合で実行可能性を確認し、新しい文脈・テンプレート系列で後の確認を行う。
旧CLDR割当の954項目はすべて使用済みである。新しい文脈を作っても絵文字自体が未使用に
戻るわけではない。二つの退役済みターゲットbankも開かない。

文脈に依存した絵文字解釈には、既に[EMODIS](https://arxiv.org/abs/2511.07193)という
関連研究がある。貢献候補は、文脈による曖昧さの存在ではなく、出力につながる因果検証である。
[Zhang and Nanda](https://arxiv.org/abs/2309.16042)が示した指標・破壊方法への依存性と、
[Heimersheim and Nanda](https://arxiv.org/abs/2404.15255)の介入解釈も踏まえる。

## 公開の構成

**第一候補は、改訂プレプリントと再現用成果物をZenodoへ置く形。** 論文と独立に引用する
コード・データ集を別レコードにして相互参照する。論文からは、実際の結果に対応する成果物の
特定版を引用する。Zenodoは公開前のDOI予約と、版を結び付けた更新に対応するが、予約だけ
では公開完了にならない。公式の[DOI案内](https://help.zenodo.org/docs/deposit/describe-records/reserve-doi/)
と[版管理](https://help.zenodo.org/docs/deposit/manage-versions/)を参照。

**arXivを使わない別案は、本文をTechRxiv、成果物をZenodoへ。** IEEEの
[公式案内](https://innovate.ieee.org/techrxiv/)では、CS等の無料プレプリントサービスとして
説明されており、公開前のスクリーニングは査読ではない。
[DOIの説明](https://innovate.ieee.org/wp-content/uploads/2023/03/TechRxiv-Sell-Sheet-Final-4.13.2022-1.pdf)もある。
詳細FAQは今回確認できなかったため、現行のアカウント・識別子の要件は投稿前に確認する。

JSTの[Jxiv](https://jxiv.jst.go.jp/jxiv_docs/ja/Jxiv_about_ja.html)も英文とDOIに対応するが、
後から自由に追加できるミラーとは扱わない。
[2026年6月版ガイドライン](https://jxiv.jst.go.jp/jxiv_docs/ja/Jxiv_guidelines_ja.html)には、
他所に先に投稿・公開した原稿と同時投稿への制限、査読コメントを反映した版への条件がある。
今回の原稿について、その条件を確認してから選ぶ必要がある。

**将来の代替案は、本文をarXiv、コード・データをZenodoへ。** 著者は現在arXivへ
投稿できないため、これは当面の公開経路にはしない。arXivにもDOIが付く。
初回や新しい分野での投稿ではendorsementが必要になる場合があり、moderationもある。
公開の候補であって、掲載保証や査読採択ではない。[DOI](https://info.arxiv.org/help/doi.html)、
[endorsement](https://info.arxiv.org/help/endorsement.html)、
[moderation](https://info.arxiv.org/help/moderation/index.html)を参照。

同じ成果物に識別子を発行する前に、本文の主な公開先を決める。論文に既存DOIがある場合は
Zenodoの案内に従ってそれを指定する。論文DOIを別のコード・データ集に流用しない。
FigshareもDOI付き公開の候補だが、今回の計画に必須の機能を追加するわけではない。

記名版プレプリントには、正確な所属、資金・AI協働の開示、会議採択を示唆しない体裁、文献、
版・日付、公開資料による再現範囲を記す。9月の投稿版と添付資料は過去の版として保存する。
含めるコード・データの再配布条件を確認し、モデル重み、ローカルパス、非公開の査読本文は
入れない。生の活性を公開しない場合は、集計値からの再計算までという制約を明記する。

## 今回確認した計算環境

最初の`spiral status`ではRTX 5090が空いており、GPU計算プロセスはなかった。
その後、既存3Bモデルの全ファイルを過去のartifact-manifest固定値と照合し、
利用可能な既存Torch環境を確認した。PDF確認後、独立したcheckoutで応答パイロットを
実行し、各実行直前にも空きを確認した。[結果報告](CONTEXTUAL_EMOJI_OUTPUT_PILOT_V0_RESULTS.ja.md)に
実際の環境、全採点セル、独立した数値検算を残した。終了後にもGPU計算プロセスはなかった。
これは取得完了の確認であり、因果介入の正しさを証明するものではない。

次の実験は新しい作業用checkoutで進め、GPUを使う直前に再度空き状況を確認し、
完了した小単位の結果を保存する。開発は固定した3Bの1構成から始め、設計を固定した後に
第2のモデル系列で主張を検証する。大きなモデルや大規模な図鑑への拡張は、指標が役立つと
確認できてから進める。

## 記述的な集計の再生成

```bash
python3 scripts/summarize_revision_sensitivity_v0.py
```

既定では決定論的なJSONを標準出力に表示し、ファイルを変更しない。`--output`では
新規パスを指定でき、既存レポートの上書きは拒否する。ハッシュはどの入力を使ったかを
記録するもので、欠けている科学的な前提を補うものではない。
