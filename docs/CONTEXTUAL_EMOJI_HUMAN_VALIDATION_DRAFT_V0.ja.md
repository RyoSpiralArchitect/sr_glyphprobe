## 1. 問いと、分けて扱う二つの集団

独立した読者は、目標とcueの関係を著者の想定どおりに読むだろうか。また、候補文の言い換えは比較可能な選択肢を表しているだろうか。

- **既存の開発課題の事後的検証：** 6系列・24課題を対象とする。モデルの結果はすでに観察済み。人の回答から課題の妥当性を支持・否定できても、この集団を確認用標本には変えられない。
- **後続の独立系列の研究：** 採用した人による検証手順に沿って、これまでの研究文脈に露出していない独立の担当者が新しい版のbankを用意する。既存6系列の名前や言い回しだけを変えても独立した系列にはならない。保護された過去のbankは開かない。

モデルの確率、著者が定めた向き、人の回答は別々の記録である。AIによる下書きや批評を独立した人のラベルにはできない。計算上の整合性が確認されても、意味や候補文の同等性は検証済みにならない。

### 最初の段階：スコアと想定ラベルを伏せた著者評価

最初の評価者は、研究の議論とモデル結果の集計をすでに見た**研究著者1名**とする。assistantが提示内容を準備して対応表を分離し、著者本人が回答する。位置付けは**スコア・想定ラベルを伏せた著者による開発用pilot**であり、独立した人による検証や完全な盲検研究とは呼ばない。独立した第三者の評価者はまだ確保していない。著者1名の回答から評価者間一致を推定したり、独立検証を完了したことにはできない。

問題を提示する前の準備条件を、次のように定める。

- 中立的な表示ID、課題文、候補文、回答欄だけを見せる。モデルのスコアと順位、想定ラベル、元の実験・項目ID、項目の選定理由、表示された候補と元の候補の対応は伏せる。実際の絵文字・単語は見えるため、手がかりの種類、繰り返し出る材料、著者がすでに知っている内容までは隠せず、忘れたことにもできない。
- 回答の前に項目一覧、出題順、釣り合わせた候補提示順を決め、モデルの成績を基準に選定・配列しない。評価者用材料、元の想定回答・向きの対応表、割り当て・提示順の対応表を別々の3点として版とハッシュを付け、最初の回答前に記録する。seedと対応表は評価者用材料に入れず、後の回答が異なっても元の想定ラベルは保存する。実際の範囲・割り当て・反復数は **OPEN**。
- HTML、JavaScript、非表示欄、取得可能なmetadata、同梱の評価者用ファイルに答えの対応表を埋め込まない。評価者用の書き出しは許可した項目だけで作り、渡す前に漏れを検査する。これは偶発的な露出を防ぐ措置であり、所有者が自分の研究ファイルを調べても読めないという安全性の保証ではない。
- 解釈の回答を先に集める。その段階の回答確定まで、項目ごとの正誤、モデルとの一致、ヒント、途中の集計を見せない。同等性・手がかり比較の画面や答え合わせへ進む前に回答を確定する。後の訂正・裁定は、理由付きの別記録として保持する。
- 事前の関与、見覚えのある項目、繰り返しの露出、不確実さ、棄権、未完了を記録する。曖昧な回答や想定に反する回答も残す。同じ著者が見る類似条件を独立した評価には数えない。評価の順序で追加の露出は減らせても、先に見た内容の影響を消したり、後の比較を独立にすることはできない。

この段階では、説明の分かりにくさ、課題の曖昧さ、候補文の違いを見つけ、材料の改善に役立てられる。人一般の正答率や、好ましいモデル結果の独立した確認にはならない。その後の独立評価は、設計と募集を別に判断する。

## 2. 評価課題と盲検化を分ける

| 課題 | 見せる情報 | 求める判断 |
| --- | --- | --- |
| 解釈と選択 | 一つの目標・メッセージと一組の候補文。候補の提示順を釣り合わせる | どちらの応答が導かれるか。前者／後者／両方／どちらでもない／曖昧／理解・判断困難。説明は任意 |
| 自然さ | 同じpromptと、それぞれを区別できる候補文 | promptと各候補文の理解しやすさ・自然さ。流暢さを正しさと同一視しない |
| 候補文の同等性 | 比較に必要な文脈と複数の候補組を、別の評価画面で示す | 同じ区別を表すか。意味・範囲・否定・適切さに何が違うか。不確実という回答も認める |
| carrierの情報 | 文脈中の対応するemojiと単語のメッセージを、別の評価画面で比較する | 課題に必要な情報が比較可能か。増える情報、失われる情報、不確実な点は何か |

解釈の評価者には、モデルスコア、介入結果、著者の意図した答え、実験ID、意図した対応を明かしてしまう全候補組の横並びを見せない。表示には中立的なIDを使い、提示順との対応表は別に保持する。

同等性とcarrierの評価では、解釈課題では隠す比較そのものを見せる必要がある。担当の割り当てや収集の場を分け、その回答を完全な盲検の単一入力解釈として扱わない。別の人に依頼するか、先に比較を見ないよう順序を明示して設計するかは **OPEN**。盲検が保たれたと仮定せず、先に何を見たかを記録する。

「曖昧」（複数の読みが成立する）と「理解・判断困難」（理解できない、判断できない）の違いを平易に説明する必要がある。自然さの尺度、同等性の回答選択肢、説明文、練習例は **OPEN**。著者の望む答えへ誘導する練習にはしない。

## 3. 収集前からの順序

1. 対象とする集団・表現条件を決め、cueなし条件を含める扱いも定める。課題・系列・carrier・文脈・cue・候補組ごとに予定単位を数える。モデルスコアの欠測は人の回答ではなく、補完しない。
2. 評価者の適格性、割り当て、提示順の釣り合わせ、盲検化、生の記録項目、欠測の扱い、以下の解析・裁定手順を決める。回答収集前に日付付きの版として保存する。
3. 説明文と画面が理解できるかを確認する。その確認を開発用pilotとするか、参加者・項目を後の評価に含められるかを、確認の**前**に決める。修正と露出の履歴を残す。
4. 著者pilotでは、上記の情報を伏せる条件のもとで自己評価を集める。後の独立評価では、他の評価者の回答を共有せず、独立した回答を集める。どちらも辞退、未完了、予定した割り当てからの逸脱を残す。二つの段階を独立した評価者の集まりとして合算しない。
5. 決めた手順で回答分布と不一致を集計する。後から行う裁定は理由付きの別記録とし、生の回答を置き換えない。
6. 開発段階で保てる主張・課題を判断する。修正には新しい版を付ける。後続の候補組と独立系列の設計を新たなモデル結果を見る前に決め、その判断に使った開発上の選択も残す。

## 4. まだOPENの判断

| 判断 | 決める内容 |
| --- | --- |
| 評価者と独立性 | 最初のpilotは参加を申し出た著者1名で、独立性はない。後の独立評価者の人数、募集方法、過去の関与・露出、独立性の確認方法はOPEN |
| 言語能力 | 必要な英語理解、emojiへの習熟、望む答えを基準にしない適格性の確認方法 |
| 範囲と割り当て | 評価する表現・候補組、単位ごとの回答数、系列・carrierの配分、同じ項目への再露出、提示順の釣り合わせ |
| 運用 | 謝礼、参加時の説明、プライバシー・記録の保持、辞退・撤回の具体的な方法 |
| 評価票 | 説明文、回答選択肢・尺度、練習材料、同等性・carrier用の独立した評価画面 |
| 解析 | 一致・不一致の集計、採用基準を設ける場合の閾値、未完了・曖昧回答、裁定、不確実性や多重性の扱い |
| 次の集団 | 独立の管理担当、新しい系列、実用的な効果の目標、後続研究の標本配分 |

確定したのは最初のpilotの評価者の役割と人数だけである。独立評価者数、一致率の閾値、除外規則、謝礼の支払い、審査・制度上の適合は未決定。判断に使う回答を見る前に選択を済ませ、好ましいモデル結果を保つために閾値を調整しない。

## 5. 記録、分母、結果の分岐

仮名化した評価者IDと、版を持つ項目・説明文IDを使う。評価課題、割り当て、実際の候補提示順、生の回答、任意の説明、欠測・棄権、関係する事前露出、後の裁定を保持する。連絡先などの個人を識別する情報は解析アーティファクトと分ける。

**予定 → 割り当て → 完了 → 採用対象** の件数と、その差の理由を、全体および課題・集団別に報告する。規則に沿った部分集合だけでなく、当初予定した全体の分母も残す。同じ課題への複数回答や言い換えは、独立した課題の数を増やさない。多数派に一致する回答だけ残して不一致を消す方針ではない。

- 解釈と候補文が支持される：別に設計した独立系列の検証へ進む。事後的な評価という位置付けは保つ。
- 曖昧さ、不自然な候補文、候補組間の意味の違いが残る：測定感度の結果を保持し、開発材料を修正した上で修正版を明示的に評価する。
- 判断が分かれる：不確実性と競合する読みを報告する。未解決の項目を「人の正答率」や因果実験の評価指標に置き換えない。

著者は情報を伏せたpilotへの参加を申し出ているが、問題の提示と回答収集はまだ始めていない。外部募集・連絡、評価サービス、新bankの取得、モデル実行、論文の主張変更、公開は今回の準備に含めない。次の成果物は、残る未決定事項を解消した版付きのpilot手順と、未記入の記録schemaである。
