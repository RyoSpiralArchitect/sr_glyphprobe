# 文脈中の手がかりを、二つの問いに分ける：開発版1

[English](CONTEXTUAL_EMOJI_TWO_TRACK_V1.md)

## 目的と位置づけ

著者pilotとその照合後に作る、次の出力を見る前の**開発設計**である。
範囲を限定した状態の一致と、通常のメッセージに近い文脈での解釈を分ける。
既存24課題・6群を再利用する。問題文の条件を増やしても独立な標本は増えない。
独立した人による検証、確認的成功、因果は主張しない。元の材料・回答・結果は保つ。

## 二つの系列、三つの命題

| 系列 | 問い | 仮定と範囲 |
| --- | --- | --- |
| 範囲を限定した状態の一致 | 報告された性質は、明示された希望の性質と一致するか | その性質について報告は正確。ただし手がかりの意味が不明なことはあり得る |
| 自然な文脈でのメッセージ解釈 | メッセージは指定された性質・感情を示唆するか | 真実性や現実の成功を保証する仮定は加えない |
| 自然な文脈での結果の証拠 | メッセージだけで、指定された実際の結果が成立したと分かるか | 設定・予報・計画・提案と、その実現を区別する |

各命題への回答はYes/No。人の画面では、その前に独立した必須の二択で
**「この問いへの答えを決められるか」**を尋ねる。決められないときの命題回答は
未確定のまま保存し、Noに変換しない。言葉の分かりにくさ、足りない文脈の理由も
別に残す。これは構造化された判断であり、自由会話や独立した正解ではない。

表情群では問い自体が変わる。限定系列は見た目の笑顔・涙、自然な文脈の系列は
表現された喜び・悲しみを尋ねる。他の群も、広い実用的目標から温度・設定・状態・
方向・予報の種類へ範囲を狭める。したがって系列差を「指示だけの因果効果」と
読まない。難しい群も含め、改訂した問題文の全一覧を残す。

## 出力を見る前に定めるモデル検証

既存のLlama 3.2 3B BF16をオフラインで使う。既に検査したeager attentionと
候補間で形状をそろえる採点を再利用する。モデル追加取得・自由生成はしない。

- 24課題 × 2文脈 ×（絵文字2種＋単語2種＋手がかりなし1種）× 3命題 ×
  問いの肯定・否定2種＝**1,440候補対**。
- 結果の証拠には、正確な完了報告が明記される対照と、結果が不明と明記される
  対照を加える。24 × 2文脈 × 2対照 × 2極性＝**192候補対**。
  これらは論理的な動作確認であり、絵文字条件や通信の意味の発見ではない。
- 合計**1,632候補対／3,264系列採点**と、過去の値の厳密再現32回で、
  **最大3,296 forward**。独立課題数は24のまま。
- 回答候補は常に ` The answer is yes.` と ` The answer is no.`。
  “Is it true that …?” と “Is it false that …?” の両方を残し、
  極性反転への感度を測る。反転は証拠の標本数を増やさない。
- 採点前にローカルtokenizerで分割し、文字列・token ID・ソースハッシュ・
  モデルと実行環境を保存する。問題文のtoken列が候補接続で変わる場合は停止する。
- 候補の長さを揃え、同じ矩形をFP32で正規化し、有効な候補tokenだけ採点する。
  共通接頭部分のlogitと確率は完全一致を要求する。前後の過去入力も厳密一致を要求し、
  失敗時も予定行と欠測を残す。
- 読込前と各forwardの前後で他のGPU PIDを検査する。読込前12 GiB、境界で4 GiBの
  空きが必要。Torch上限9.5 GiB＋driver分0.5 GiB、実行上限30分。
  競合時は自分だけ停止し、自動再試行や他の仕事への変更はしない。

全ての手がかり種・群・命題・極性・論理対照、欠測、token和、接頭部一致、
極性反転時の不整合を報告する。Yes−Noの系列log確率差と、2文脈×2手がかりの
差の差は記述的なモデル挙動として扱う。有意差、後付け閾値、人の正答率、
絵文字優位は主張せず、原稿の数値を自動で置き換えない。
手がかりなし対照を、二種類の手がかりについて重複した標本として数えない。

## 評価画面と、人による検証の条件

次の著者試用は24課題各1条件。限定系列12問・自然な文脈12問、絵文字12問・単語12問。
各群で系列×手がかり種の4条件を1つずつ、文脈×手がかりの4組合せも1つずつ割り当てる。
新しいモデル出力を見る前に固定したseedと材料だけで割り当て、回答一致率は使わない。
限定系列は命題1つ、自然な文脈は命題2つで、実質36判断。
自然な文脈の二問は同じ画面で見えるため、問いによる読みの誘導は限界として残る。

白地・青アクセントの読みやすいv0の構成を引き継ぎ、一つの場面、分離した問い、
二択、任意の理由・メモ、保存・見直し・明示的な確定を置く。希望どおり画像生成はしない。
英語への慣れ、研究への接触、モデル結果への接触、以前の回答と想定の照合への接触、
各問題への見覚えを分ける。著者は既に結果に接しており、自己申告でその履歴を上書きしない。
正解やモデル結果は表示しない。回答は端末内のGit・共有領域外に保存する。
完了済みv0のファイルと実行中のサーバーは変えない。

より大きい独立検証には、独立した評価者、独立に用意した新課題群、回答前の解析方針、
判断不能の扱いが別途必要である。今回の試用で操作や文言を改善できても、人の意味判断の
妥当性を確立したり、好都合な群だけ選んで確認的主張に進めたりはしない。

## 再現

`scripts/contextual_emoji_two_track_v1.py inventory --output PATH` でモデルなしの
一覧を作る。`package --output PRIVATE_DIRECTORY` で材料だけから非公開評価票を作る。
どちらも人の回答やモデルスコアを読まない。別の実行器がtoken列を準備し、保存済み仕様
だけからモデルを採点する。push・公開・募集・原稿更新・学習は今回に含めない。
