# 共通接頭列診断のCPU再検算を移植可能にする補足

[English](CONTEXTUAL_EMOJI_PREFIX_PREFLIGHT_ADDENDUM_V0.md) · [当初の仕様](CONTEXTUAL_EMOJI_PREFIX_CONSISTENCY_V0.ja.md)

2026-10-07（JST）。モデルを一度も実行していない段階で、CPU再検算用の参照表現を別版として定める。選択済み8入力、各7回・最大56回の実行、BF16の実行環境、資源上限、モデル出力の許容差0という条件は変更しない。

## 初回の実行前停止

commit `d725960` が用意した仕様のSHA-256は `28c164b6e9cc0dfc1dae11b2c11ff84118f6d7f289c2122999d1cae9ac0253d7`。炉ではCPU解析全体の再計算照合で停止した。runディレクトリ作成、モデル実行環境のimport、モデルメモリ確保、forwardはいずれも行っていない。モデルの失敗観測ではなく、0 forwardの実行前停止である。

Linuxでの再計算は、Macで保存した解析の `coefficient_change_rows/*/mean_squared_cell_shift` の7箇所だけ異なった。行番号は10、32、45、75、84、85、94。各差はbinary64の1 ULPであった。元の式は4つの差を `** 2` で二乗した平均である。候補接頭列の全記録と全Hを含め、ほかの項目は一致した。低水準の原因までは同定していない。

## 別版の参照記録

schema version 2では、独立した `measurement_portable_replay.json` を置く。係数変化144行すべてについて、該当する補助量を `math.fsum(d * d for d in four_differences) / 4` として再構成する。解析全体、元記録のhash、再計算ソースのhash、元記録から変わった値をそのまま保存する。元の解析JSONと解析ソースは変更しない。

改訂した検査は、次の条件を要求する。

- 元の解析、解析ソース、raw記録、取得ソースのhashが一致すること。
- 各端末での元解析の再計算差が、明示した補助量以外に生じていないこと。
- raw記録からの決定的な再計算と、固定した元解析からの再構成が、全項目で完全一致すること。
- 再計算結果全体が、新しい参照記録およびそのhashと完全一致すること。数値の許容差は導入しない。
- 選択入力、元のモデルスコア、実行環境の完全一致条件が以前と同じであること。

これはCPU上の補助的な集計量の計算定義を別版にする変更であり、元のモデル採点の修復を示すものではない。端末固有の差はrunの来歴に残す。新仕様は `validation/contextual_emoji_prefix_consistency_v0/portable_preflight/` に置く。当初の仕様は元の場所に残し、当初のcommitから再現できる。

この変更時点では、新しいモデル出力を一つも観測していない。修正後の実行前検査によってモデル試行数の上限56回は増えない。後でモデル側の条件に不合格となれば、その結果を残す。この補足は精度設定の探索や全課題の再実行を許可するものではない。
